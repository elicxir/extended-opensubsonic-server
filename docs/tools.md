# 補助ツール

サーバーの外で動き、見つけた関係を `/ext/suggestions` に候補として送るツールです。候補は承認するまで取り込まれません（[ext-api.md](ext-api.md) の「候補と推定」）。

| ツール | 調べるもの | 必要なもの |
| --- | --- | --- |
| `mb-match` | MusicBrainz の録音・作品・編曲の関係から、楽曲と編曲 | インターネット |
| `audio-match` | 音そのものを比べて、編曲がどの原曲を弾いているか | 音楽ファイル（読むだけ） |

どちらも Docker イメージ `eos-tools` に入っていて、`compose.yaml` の `tools` サービスで動かします（`up` では起動しません）。API キーは `eos-admin apikey create` で作り、`EOS_API_KEY` で渡します。

```sh
export EOS_API_KEY=eos_...
docker compose run --rm tools audio-match --album "Piano Pieces" --against "Original Soundtrack" --dry-run
docker compose run --rm tools mb-match --album "Original Soundtrack" --dry-run
```

`--dry-run` を外すと候補を送ります。`--help` で全部の項目を表示します。

## audio-match

`--album` に挙げたアルバム（ピアノ版、オーケストラ版、リメイクなど）の曲ごとに、候補の曲と音を比べ、はっきり似ている曲が 1 つあれば「その曲の編曲」という候補を作ります。

### 比べ方

カバー曲の検出でよく使う方法です。

1. 曲を 12 の音名の強さ（クロマ、CENS）に変えます。1 秒に約 2 回、2 秒ほどならします。楽器や音量ではなく、和音と旋律の動きを見ます。
2. 候補の曲を、全体の音名の分布がいちばん合う 2 つの調に移して比べます（移調しても見つかります）。
3. 3 回分の窓どうしで、互いに近いものを「一致」とします。
4. 一致の表の上で、いちばん長く続く共通の部分を探します（Smith-Waterman。テンポの違いや省略を許します）。

その長さの点数が、他の候補と比べてどれだけ抜けているか（z）で判断します。

| z | 候補 |
| --- | --- |
| `--min-z`（既定 8）以上 | 確信度 0.9 |
| `--low-z`（既定 4）以上 | 確信度 0.6 |
| それ未満 | 出しません |

候補の曲が `--min-candidates`（既定 8）より少ないと z が当てにならないので、その曲は飛ばします。

### 候補の曲

- `--against` を指定したときは、名前にその文字を含むアルバムの曲です（原曲のサントラを指定するのが確実です）。
- 指定しないときは、作曲者が同じ曲すべてです（`--album` のアルバムは除きます）。別の編曲（他のピアノ版など）がいちばん似ることがあるので、根拠の上位 3 曲を見て判断してください。

### 送る候補

`link_arrangement` を 1 つの原曲と 1 つのアルバムごとに作ります。

- 原曲がもう楽曲に入っていれば、その楽曲（`composition.id`）に入れます。入っていなければ、原曲の曲名と作曲者で楽曲を作り、原曲も一緒に入れます（`originalTracks`）。
- 編曲の名前はアルバム名です（名前から種類を推測します。例：「ピアノ」「Piano」なら piano）。曲に `ARRANGER` があれば編曲者にします。
- `rule` は `audio_match`、`origin` は `audio`、`model` は `chroma-qmax/1` です。`evidence` に z と、上位 3 曲の点数を入れます。

### 速さ

- 特徴の計算は 1 曲に 1 秒ほどで、`--workers` 個（既定は CPU の数）を並べて計算します。結果は `/data/cache/audio-match` に保存し、次からは計算しません。
- 比べるのは 1 組に数ミリ秒です。候補を `--against` で絞ると速くなります。

### 得意でないもの

- 主題を大きく変奏した曲（ラプソディや変奏曲）。共通の部分が短いと z が上がりません。
- 1 曲の中で何曲もつなぐメドレー。いちばん長く使われた 1 曲だけが見つかります。
- 曲名だけ同じで音が違うもの、効果音や短いジングル。

実際のライブラリ（浜渦正志の作品）で試した結果です。

| アルバム | 結果 |
| --- | --- |
| ピアノ作品集 δ・ε・T_Comp1（19 曲）と α CLOCK | 19 曲すべて正しい組が 1 位（z 11〜99） |
| Piano Pieces "SF2"（25 曲）と SaGa Frontier II のサントラ | ピアノ曲 18 曲のうち 16 曲が z 8 以上。オーケストラのラプソディ 6 曲は 1 曲だけ |

## mb-match

アルバムごとに MusicBrainz のリリースを探し、ディスクと曲の位置（長さで確かめます）で録音と組にし、録音が演奏している作品と、作品どうしの「編曲」の関係から、楽曲と編曲の候補を作ります。

- `--aliases`：作品に結びつかなかった曲を、曲名で MusicBrainz の作品名と別名から探します。作曲者のタグが作品の作曲者と一致するものだけを使います。「Bloody Tears」と「血の涙」のように、別名として登録された別の言語の曲名がつながります。
- `--titles`：作品の親（`parts`）を作品（`COLLECTION_WORK` に当たるもの）にする候補も作ります。
- 候補の出所（`origin`）：録音と作品・編曲・親の関係から作るもの（`musicbrainz_work`・`musicbrainz_arrangement`・`musicbrainz_parts`）は `external`、別名で探したもの（`musicbrainz_alias`）は `name` です。MusicBrainz が「この録音はこの作品」と書いているのは前者だけだからです。`originRef` は作品の URL です。
- MusicBrainz には 1 秒に 1 回までしか問い合わせません。全部のアルバムを調べると時間がかかるので、`--album` で絞れます。
